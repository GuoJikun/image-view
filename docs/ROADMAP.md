## P0 已完成（v1.0 / v1.1）

### v1.0 查看器基线

- [x] 打开：文件对话框、命令行、拖放；目录自然排序与上一张/下一张（不循环）。
- [x] 显示：Fit（不放大）/ 100%（1 图像像素 = 1 物理像素）/ 缩放 1%~3200% / 平移与边界钳制。
- [x] 异步解码：单解码线程、latest-wins、旧结果丢弃；加载中 spinner。
- [x] 大图保护：单边 8192、40 MP 纹理上限、250 MP 原图拒绝；降采样标记。
- [x] 体验：状态栏、窗口标题、错误横幅与重试、透明棋盘格、帮助窗口、全屏。
- [x] 质量：单元测试 + 手工矩阵 + release 构建（验收记录见 [PLAN-P0.md](PLAN-P0.md) §9.5）。

### v1.1 体验完善

- [x] EXIF 方向自动校正（JPEG/TIFF/WebP）。
- [x] `R` / `Shift+R` 几何旋转 90°（不重传纹理）。
- [x] `F11` 全屏。
- [x] 幻灯片：3s 间隔，`Space` 开始/停止，手动翻页重置计时，末张自动停止。
- [x] 相邻图片预加载（`Open` 优先，>30 MP 跳过）+ 3 张 LRU 纹理缓存（≤72M 像素）。

**质量基线**：37 个单元测试；`cargo fmt --check`、`cargo clippy --all-targets -- -D warnings`、`cargo test`、`cargo build --release` 全部通过；release exe 约 16.8 MB。

## 进度维护规则

1. **完成子项**：先在对应阶段计划（`PLAN-P1.md` 等）勾选条目，再更新本文件的里程碑状态、进度百分比与“最近完成”。
2. **里程碑完成**：填写完成日期，重算阶段进度（已完成里程碑 / 总里程碑），并更新“当前焦点”为下一个里程碑。
3. **发布版本**：记录版本号、commit/tag、验收记录链接与 release 体积；在 `CHANGELOG.md` 新增对应章节，并归档安装包与 `SHA256SUMS.txt`。
4. **需求变更**：新需求先归入 P1/P2/P3，不允许存在“无阶段需求”；跨阶段移动或取消时，在目标阶段的变更记录留痕，并同步本文件。
5. **暂停/取消**：状态改为 ⏸ / ❌，在里程碑表备注原因，不直接删除条目。
6. **P0**：已完成并冻结范围；新需求一律进入 P1 或之后。

## 质量门禁

每个里程碑合并前必须通过：

```text
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test
cargo build --release
```

发布前额外要求：

- 在本文件更新阶段状态与“最近完成”。
- 在对应阶段计划中补充验收记录（环境、方法、实测数据、未覆盖项）。
- 手工回归 [PLAN-P0.md](PLAN-P0.md) §9.2 矩阵中受影响的类别；新增格式/解码器补夹具。
- 记录 release 体积、启动时间与目标场景内存占用；超出 [PLAN-P0.md](PLAN-P0.md) §10 预算需说明原因。
