## 1. 目标与范围

**目标**：在 v2.0 的查看器/图库基础上，补齐专业用户关心的格式（RAW、HDR）、超大文件性能（流式/GPU）、可扩展性（插件）、桌面产品成熟度（设置、多窗口、大目录架构），以及从 P1 移出的图片基础编辑（旋转/裁剪/另存）。

**非目标**：云同步、AI、移动端/Web、协作（均属 [PLAN-P3.md](PLAN-P3.md)）。

**进入条件**：P1-M1 ~ P1-M5 已完成，v2.0 已发布并稳定；每项独立评估收益与安装包体积。

## 3. 里程碑详情

### 3.1 P2-M1 RAW 支持（5~8 d）

- [ ] 常见 RAW 首帧预览：CR2 / CR3 / NEF / ARW / DNG（先做内嵌 JPEG 预览）。
- [ ] 全尺寸解码（`rawloader` 或 `libraw` 绑定），按相机型号分批支持。
- [ ] 最小可用色彩链路：色彩矩阵 + 白平衡，接入 P1-M3 的 ICC/sRGB 转换。
- [ ] 扩展名、文件过滤器、图库索引同步识别 RAW。
- [ ] 解码失败时给出“机型/格式暂不支持”的具体提示。

**验收**

- 每种已支持机型至少 3 个样例可显示、可旋转、可翻页。
- 内嵌预览路径首屏 < 500 ms；全尺寸解码不阻塞 UI。

**依赖**：[PLAN-P1.md](PLAN-P1.md) P1-M3。

**风险**：格式碎片化、解码慢、许可差异 → 按机型分批支持，未支持的机型明确降级到内嵌预览。

### 3.2 P2-M2 HDR / 10-bit 完整链路（4~7 d）

- [ ] HDR PNG / AVIF / HEIF 识别与解码（含 10-bit / 12-bit 源）。
- [ ] wgpu 表面格式与色调映射；SDR 显示器上的回退策略。
- [ ] 评估 `egui` 纹理格式限制，必要时绕过 `TextureHandle` 直接走 wgpu。
- [ ] 状态栏标注当前色彩空间、色深与是否发生色调映射。
- [ ] 与 P1-M3 的 ICC 转换共用一条处理链，避免双重转换。

**验收**

- 10-bit 渐变图在 HDR 与 SDR 显示器上均无色带、无明显过曝。
- 关闭 HDR 支持时行为与 v2.0 一致，不崩溃。

**依赖**：P1-M3。

**风险**：egui/eframe 对浮点纹理与色彩空间支持有限 → 先做 PoC 验证可行路径，再决定是否引入自定义渲染通道。

### 3.3 P2-M3 分块流式加载与 GPU 解码（5~8 d）

- [ ] 超大图（>250 MP）渐进显示：先低分辨率占位，再按视口替换。
- [ ] tile 金字塔与按视口请求；后台多重解码。
- [ ] 网络路径/可移动介质的渐进读取与失败恢复。
- [ ] GPU 解码（D3D11VA / NVDEC）能力探测与回退。
- [ ] 内存预算与 tile 淘汰策略，避免与主纹理缓存冲突。

**验收**

- 500 MP 图片可打开并在 2 s 内出现可用预览；缩放/平移不卡死。
- 无 GPU 解码能力时自动回退 CPU 路径，功能不缺失。

**依赖**：P1-M5 的缩略图/索引架构。

**风险**：复杂度高、收益集中在极端尺寸 → 先交付“低分辨率占位 + 全图替换”，tile 金字塔作为第二阶段。

### 3.4 P2-M4 插件与脚本扩展（4~6 d）

- [ ] 内部脚本能力优先（Rhai 或 Lua）：批处理、导出、重命名。
- [ ] 第三方格式解码插件接口（稳定 ABI 或 WASM 沙箱）。
- [ ] 能力授权模型（只读 / 写盘 / 网络），默认最小权限。
- [ ] 插件清单、版本约束与签名校验。
- [ ] 插件崩溃隔离，不影响主进程。

**验收**

- 示例插件可注册一种新格式并正常显示。
- 未授权能力的插件调用被拒绝且有清晰日志。

**风险**：安全与兼容成本高 → 先内部脚本后开放生态，插件 API 在 v2.x 内保持实验性。

### 3.5 P2-M5 设置、主题与快捷键自定义（2~3 d）

- [ ] 可视化设置面板（外观、浏览、缓存、性能、更新）。
- [ ] 浅色 / 深色 / 跟随系统主题。
- [ ] 快捷键重绑定，冲突检测与“恢复默认”。
- [ ] 设置 schema 版本迁移，旧配置自动升级。
- [ ] 设置项实时生效或明确标注需重启。

**验收**

- 修改设置后重启保持；配置版本升级不丢用户数据。
- 冲突快捷键被阻止并有提示。

**依赖**：P1-M1 的持久化基础。

### 3.6 P2-M6 多窗口、多显示器与会话（2~4 d）

- [ ] 独立窗口打开多张图；每窗口独立 `ViewState` 与目录。
- [ ] 共享解码线程与纹理缓存，避免重复解码。
- [ ] 跨显示器 DPI 变化正确处理。
- [ ] 会话恢复：退出时记录打开的窗口与位置，启动可恢复。
- [ ] 窗口级快捷键作用域与焦点管理。

**验收**

- 两个窗口浏览不同目录互不干扰；拖动到不同 DPI 显示器后布局正确。
- 会话恢复后窗口数量、位置、当前图片一致。

**风险**：egui 多 viewport 支持与 DPI 切换的边界行为需专项测试。

### 3.7 P2-M7 超大型目录与缓存架构（3~4 d）

- [ ] 10 万+ 文件目录可用；后台增量扫描。
- [ ] SQLite 索引（路径、mtime、尺寸、标签）。
- [ ] 缩略图磁盘 LRU 与缓存清理入口（含占用统计）。
- [ ] 索引损坏/版本不匹配时自动重建且不阻塞启动。
- [ ] 搜索与筛选走索引，避免全量重扫。

**验收**

- 10 万文件目录首次索引可后台完成，期间 UI 可用；二次启动秒开。
- 缓存清理后占用下降，且不影响正在浏览的图片。

**依赖**：P1-M5 / P1-M6。

### 3.8 P2-M8 基础编辑（2~3 d，从 P1 移入）

> v2.0 不包含编辑能力；本项是 v2.1 的首选交付，依赖 P1-M6 的图库索引与选中项。

- [ ] 旋转 / 翻转 / 裁剪；裁剪提供常用比例与自由裁剪。
- [ ] 格式转换与另存（JPEG / PNG / WebP，质量选项）。
- [ ] 非破坏原则：编辑默认只写副本；覆盖原文件必须二次确认。
- [ ] 另存时应用 EXIF 方向、保留可保留的元数据。
- [ ] 编辑结果与画布显示一致；失败时保留原文件并给出可读错误。

**验收**

- 另存结果与画布显示一致（含旋转方向）；原文件不被隐式修改。
- 取消/失败路径不产生半成品文件。
- 批量编辑（若做）逐项报告成功与失败，不因单张失败中断。

**依赖**：P1-M6 图库索引（选中项、批量入口、元数据来源）。

**风险**：编码器质量参数跨格式差异大 → 先做“旋转/翻转 + 另存 JPEG/PNG”，裁剪与 WebP 质量细分放后续小版本。

## 4. 依赖与风险

| 依赖 | 说明 |
| --- | --- |
| P1-M1 设置持久化 | M5 设置面板、M6 会话恢复的存储基础 |
| P1-M3 ICC/色彩 | M1 RAW、M2 HDR 共用色彩链路 |
| P1-M5 缩略图与索引 | M3 流式加载、M7 大目录架构的前置 |
| P1-M6 图库 | M7 索引与搜索的数据来源；M8 编辑的选中项与批量入口 |

**整体风险**：P2 每项都可能显著增加复杂度与安装包体积 → 全部以独立 feature/可选组件交付，允许单独取消而不影响已发布能力。

## 5. 验收与发布

- 每个里程碑合并前通过 [ROADMAP.md](ROADMAP.md) 的质量门禁。
- 新增解码器/格式必须补夹具，并回归 [PLAN-P0.md](PLAN-P0.md) §9.2 手工矩阵。
- 性能预算沿用 [PLAN-P0.md](PLAN-P0.md) §10；超出时在验收记录中说明原因。
- 完成后更新 [ROADMAP.md](ROADMAP.md) 的状态、完成日期与“最近完成”。
