## 1. 定位

P3 探索的是“从单机看图工具走向平台化”的方向：跨设备、智能化、可扩展生态与企业可管理性。

**共同前提**

- 核心逻辑已抽成平台无关 crate（`image-view-core`），UI 与平台能力解耦。
- P2-M4 插件接口与 P2-M5 设置体系已稳定。
- 有明确的用户需求与投入产出评估，而不是“技术可行就做”。

## 3. 方向详情

### 3.1 P3-M1 云同步与分享

- 目标：从 WebDAV / S3 / 图床直接浏览与上传；生成分享链接。
- 要点：凭据安全存储（Windows Credential Manager）、断点续传、只读缓存。
- 风险：网络错误处理与隐私；默认关闭，需显式授权。

### 3.2 P3-M2 AI 辅助

- 目标：本地或可选的模型能力，如超分、去噪、背景移除、自然语言搜索。
- 要点：优先本地推理（ONNX Runtime / DirectML），模型按需下载；结果明确标注“AI 处理”。
- 风险：模型体积、硬件差异、隐私与许可证。

### 3.3 P3-M3 移动端 / Web

- 目标：复用解码、缓存、视图数学等核心 crate，提供平板/浏览器版本。
- 要点：先把平台无关逻辑抽成 `image-view-core`；Web 端用 WASM + Canvas/WebGPU。
- 风险：`egui` 在移动端/触控交互的成熟度；文件系统访问差异。

### 3.4 P3-M4 插件市场与主题生态

- 目标：插件/主题的浏览、安装、更新与评分。
- 要点：清单签名、版本约束、崩溃隔离；服务端成本评估。
- 依赖：P2-M4、P2-M5。

### 3.5 P3-M5 协作标注与审阅

- 目标：图片上标注、评论、版本对比，适合设计/摄影审阅流程。
- 要点：标注以 sidecar 保存；可选共享链接；权限模型。
- 风险：从单机工具转向协作产品的范围跳跃 → 仅在明确需求后启动。

### 3.6 P3-M6 企业部署与可管理性

- 目标：MSI/企业分发、组策略模板（ADMX）、代理与离线更新、审计日志。
- 要点：静默安装、配置锁定、可选遥测（默认关闭）。
- 依赖：P1-M7 发布工程。

## 4. 启动前置检查

对任一方向，启动前至少回答：

1. **用户价值**：解决谁的什么问题？现有替代方案是什么？
2. **成本**：维护成本、安装包体积、服务端/证书开销。
3. **边界**：是否违背“轻量、本地优先、默认不联网”的产品原则。
4. **验收**：能否写出可量化的验收标准？不能则继续留在 P3。
5. **拆分**：能否拆成 1~2 周内可交付的独立里程碑？
