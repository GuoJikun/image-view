## 1. 方案定位与改进点

### 1.1 一句话定位与风格名

| 项 | 内容 |
| --- | --- |
| 风格名 | **暗房 · Depth Frame（纵深框架）** |
| 一句话定位 | 把三块平铺灰条重构为一条有明度纵深的连续**画框**，用分组胶囊与语义化状态替代零散图标按钮，让图片成为界面里唯一的亮源与唯一焦点 |
| 保留的原则 | 外壳交给系统、内容自己画；中性灰 + 单一强调色；画布恒深色、图片最大对比度 |
| 明确不做的 | 版式 B 的原生菜单栏（`muda`）、Tauri / Iced 迁移、任何新依赖、任何新设置项与 i18n 文案键 |

### 1.2 相对版式 A 的 5 个改进点

| # | 改了什么 | 版式 A 现状 | 为什么更好 |
| --- | --- | --- | --- |
| 1 | **三块平铺灰条 → 三级明度纵深** | 工具栏、缩略图条、状态栏、控件底、轨道由 5 个各自为政的中性灰组成；深色下缩略图条比工具栏更暗、更接近画布，像被画布吞掉；三者只靠 1 px 线与画布硬切 | 统一为「画布 S0 → 框架 S1 → 控件 S2 → 浮层 S3」四级阶梯，浅/深主题同构；画布四周加 1 px 内画框，把图片"装进框里"，层级一眼可辨 |
| 2 | **零散间距 + 竖线分组 → 分组胶囊 + 8/12 节奏** | 顶栏出现 10 / 12 / 9 / 4 / 12 五种间距，用 1×18 竖线切分；右侧"排序"是文字按钮，与纯图标按钮混排；英文长文案在 480 px 最小宽度下的排版未被实测确认 | 相关操作收进带 1 px 描边的圆角胶囊，组间距统一 12、组内 2、窗口边距 16；去掉竖线，密度均匀；窄窗口按优先级把文字按钮降级为图标（功能仍可达） |
| 3 | **active 与 hover 同底色 → 六态矩阵 + 强调色仅表"当前状态"** | 开启态与悬停态共用同一层中性叠色底，且开启时直接把图标染成强调色；强调色同时出现在图标、选中环、主按钮、进度条；菜单单选项只有文字高亮、egui 默认复选框在深色下几乎看不清（源码注释已记录该问题） | 默认 / hover / 按下 / 选中 / 禁用 / 焦点六态各有独立底色与描边；**开启态 = 强调浅底 + 强调色图标**，hover = 中性叠色，二者不再混淆；菜单复选/单选统一自绘，选中态有明确对勾/圆点；强调色每屏只出现 1 处实心 |
| 4 | **状态栏塞满 + 顶部粉红横幅挤画布 → 元信息归栏、瞬时反馈归浮层** | 26 px 状态栏把尺寸、格式、序号、幻灯片、加载、短提示挤在一行；短提示为绿色文字且 4 秒硬切消失；错误横幅是占据一整行、把画布向下推的粉红条；全屏文件名是 13 px 纯文字居中 | 状态栏只留元信息并用字重分层；短提示改为右下角圆角 toast（带图标、渐隐）；错误改为画布内浮层卡片（不占布局、不挤画布）；全屏文件名改为带底色的胶囊；反馈更可辨且画布面积恒定 |
| 5 | **10 个混风格图标 + 语义复用 → 统一图标语言 + DPI 取整规则** | 仅 10 个图标；`Sidebar` 同时用于"缩略图条开关"和"空状态插画"；播放/暂停是实心多边形、其余是线稿，省略号是实心点；工具栏图标 17 px / 缩放控件 16 px 不一致；1 px 线在分数缩放下易糊，设计稿没有取整规则 | 统一 20×20 网格、18 pt 绘制框、1.6 pt 线宽、圆头圆角连接、全线稿；语义去重并补齐空状态/排序/复选等图标；给出物理像素对齐、圆角取整、命中区不随 DPI 变化等规则，解决 1.25/1.5/1.75 缩放下的灰边与糊线 |

## 2. 产品目标与现状痛点

### 2.1 产品目标（3 个正交目标）

| # | 目标 | 可度量标准 |
| --- | --- | --- |
| G1 | **提升图片主体性**：chrome 退到背景，画布面积恒定 | 出现错误、短提示、加载、幻灯片时画布可用高度不变；浅/深主题下画布与框架的明度差均 ≥ 25/255；全屏时框架不透明度 ≤ 72% 且文字仍 100% 可读 |
| G2 | **提升状态可读性与操作确定性**：任何"开/没开、选/没选"一眼可辨 | 六态矩阵覆盖全部自绘控件（图标按钮、分段、卡片、菜单项、复选/单选、主按钮）100%；开启态与 hover 态底色不同；菜单复选/单选选中态在浅/深主题下对比度 ≥ 3:1 |
| G3 | **提升跨主题 / 语言 / DPI 的一致性**：一套规则走遍所有组合 | 浅/深 × 中/英 × 1x / 1.25x / 1.5x / 2x 共 16 组合下无文字截断、控件重叠、1 px 线灰边；480 px 最小窗口宽度下顶栏与菜单不重叠 |

### 2.2 现状痛点（全部来自真实代码 / 效果图）

| # | 痛点 | 证据 | 影响 | 本次对策 |
| --- | --- | --- | --- | --- |
| P-1 | chrome 明度层级混乱，深色下缩略图条被画布吞没 | 现有浅色板中 chrome / 控件底 / 轨道 / 缩略图条 / 状态栏为 5 个不同灰；深色板 chrome≈42、缩略图条≈35、控件底≈58、画布≈16；`02-toolbar-dark.png` 中底部条与画布边界含糊 | 层级靠猜，图片与界面的边界不清 | 四级 elevation 阶梯 + 画布 1 px 内画框（§5.2 / §5.3） |
| P-2 | 开启态与悬停态视觉相同 | 图标按钮绘制中 `hovered || active` 使用同一底色；开启态额外把图标染成强调色；`05-spec.png`「控件状态」只给默认/悬停/按下/选中/禁用，无焦点态 | 用户无法判断"缩略图条/幻灯片是否已开启" | 六态矩阵 + 强调色使用规则（§5.4 / §5.7） |
| P-3 | 顶栏节奏零散、中英文混排风险 | 顶栏出现 10 / 12 / 9 / 4 / 12 五种间距与 1×18 竖线；排序按钮按文案宽度动态取宽（最小 62）；`docs/PLAN-P1.md` M9「未覆盖」明确写"未在真实窗口逐项截图确认英文在 480 px 最小宽度下的排版" | 英文长文案下挤压、视觉密度不均 | 分组胶囊 + 8/12 节奏 + 窄窗口降级（§5.6 顶栏） |
| P-4 | 状态信息全部压在 26 px 一行，短提示硬切 | 状态栏同时容纳尺寸、格式、色彩标记、降采样、序号、提示、幻灯片、加载指示器；提示 4 s 后直接置空（无淡出）；`06-spec-states.png` 中提示与序号挤在右侧 | 瞬时反馈容易被忽略，且与常驻信息争抢注意力 | 状态栏分层 + toast 浮层渐隐（§5.6 状态栏 / 短提示） |
| P-5 | 错误横幅引入整行粉红并推挤画布；空状态与主题脱节 | 错误横幅是独立顶部面板（粉底 + 3 px 红条）；空状态图标/标题/说明用写死的半透明白，浅深主题下完全一致；`06-spec-states.png` 可见横幅把画布压下一行 | 沉浸感被破坏；浅色主题下空状态仍像深色浮块 | 错误改为浮层卡片；空状态按主题取色（§5.6） |
| P-6 | 图标风格不统一、语义复用、DPI 规则缺失 | 图标集仅 10 个；`Sidebar` 同时用于缩略图开关与空状态；播放为实心多边形、省略号为实心点；工具栏 17 px / 缩放 16 px；`docs/PLAN-P1.md` M4「未覆盖」写"128 px 缩略图在极低 DPI 或非整数缩放显示器上可能略显模糊，尚未做多显示器 DPI 矩阵回归"；`05-spec.png` 无取整规则 | 视觉语言不成熟；分数缩放下细线发虚 | 统一图标语言 + 高 DPI 取整规则（§5.8 / §5.10） |
| P-7 | 菜单选中态弱、两套菜单样式不一致 | 溢出菜单用自绘复选框（源码注释说明 egui 默认复选框深色下"看不出来"），主题/语言单选项只有文字高亮；右键菜单 3 项与溢出菜单重复但样式、宽度不同 | 设置项"勾没勾上"难辨 | 溢出/右键/排序共用 S3 浮层与自绘复选/单选（§5.6 菜单） |

## 3. 用户故事

| # | 用户故事 |
| --- | --- |
| U1 | 作为**在深色系统下长时间看图的用户**，我希望工具栏、缩略图条、状态栏有清晰的明度层级且画布被"框"住，以便一眼分清哪里是图片、哪里是界面，不误点也不分心 |
| U2 | 作为**刚上手的用户**，我希望每个开关（缩略图条、幻灯片、主题、语言、色彩标记）的开启态与鼠标悬停态明显不同，以便随时确认当前状态而不用点一下试试 |
| U3 | 作为**用英文界面、窄窗口或高 DPI 屏的用户**，我希望顶栏和菜单在长文案、480 px 宽度、1.25/1.5/2 倍缩放下都不重叠、不截断、细线不发虚，以便获得与中文 1x 屏一致的观感 |
| U4 | 作为**批量浏览照片的用户**，我希望复制路径、删除成功等瞬时反馈以不占画布的浮层出现并柔和消失，错误也以浮层卡片呈现，以便图片始终占满可用区域、视线不被打断 |
| U5 | 作为**全屏看图的用户**，我希望界面框架退为半透明、文件名以带底色的胶囊短暂出现后淡出，以便既保持沉浸又能随时够到所有工具 |

### 5.10 高 DPI 与缩放取整规则

> `ppp` = 当前 `pixels_per_point`；所有规格值为逻辑点（pt）。

| # | 项目 | 规则 | 目的 |
| --- | --- | --- | --- |
| 1 | 单位 | 全部尺寸、圆角、间距、字号为 pt；物理像素 = `round(pt × ppp)` | 单一真值来源，避免各模块各自乘系数 |
| 2 | 1 pt 结构线 | 线宽恒 1.0 pt；整数 ppp 时线中心落在 `(round(x×ppp) + 0.5)/ppp`；分数 ppp 时落在 `round(x×ppp)/ppp` | 避免一条线跨两个物理像素产生灰边（解决 P-6） |
| 3 | 矩形 / 圆角 | 所有 `min/max` 坐标与圆角半径先 `round(v × ppp)/ppp` 再绘制；圆角半径同样取整（8 pt → 8×ppp 后 round） | 1 pt 描边不溢出、圆角不锯齿 |
| 4 | 图标 | 20×20 网格映射到 18 pt 框；线宽 `max(1 物理像素, 1.6 pt × ppp)`；关键点对齐 0.5 物理像素；端点/连接保持 round | 1.25 / 1.5 / 1.75 缩放下细线不发虚 |
| 5 | 文本 | 字号为 pt，由 egui 按 ppp 光栅化；**不手动乘 ppp**；最小 10.5 pt | 避免字重与行高漂移 |
| 6 | 命中区 | 保持逻辑尺寸（32×32、38×36、80×60 等），**不随 ppp 变化** | 鼠标 / 触控判定与快捷键行为不变 |
| 7 | 面板累加 | 56 / 96 / 28 等分区高度取整后累加，分区之间不留 1 px 缝隙或重叠 | 消除深色下的亮/暗细缝 |
| 8 | 分数缩放 | 允许 1 物理像素的描边偏移；**禁止**用半透明叠色"补像素" | 保持规则可预测、可验收 |
| 9 | 缩略图纹理 | 最长边 128 保持不变；卡片 80×60 在 2× 下需 160 物理像素，允许 ≤1.25× 放大并依赖现有 mipmap + LINEAR；若实测模糊按 Q5 回退 76×56 | 不改动解码/缓存策略 |
