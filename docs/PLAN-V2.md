## 0. 阶段划分

| 阶段 | 版本 | 主题 | 状态 | 明细 |
| --- | --- | --- | --- | --- |
| P0 | v1.0 / v1.1 | 查看器基线：打开、缩放、翻页、EXIF/旋转、幻灯片、预加载缓存 | ✅ 已完成 | `PLAN.md` §3.1 / §3.2 |
| P1 | v2.0 | 格式、色彩、连续浏览与可分发安装 | ⬜ 未开始 | [本文 §1](#1-p1v20) |
| P2 | v2.x | 专业能力与架构增强 | ⬜ 未开始 | [本文 §2](#2-p2v2x) |
| P3 | v3+ | 长期演进（新增方向） | ⬜ 未开始 | [本文 §3](#3-p3v3新增长期计划) |

**划分原则**

- **P0**：已经交付并通过验收的能力，不再改动范围。
- **P1**：v2.0 发布所需的全部功能与工程项；可以拆成多个小版本先行发布，但里程碑不变。
- **P2**：v2.0 之后、面向专业场景与架构升级的能力，不阻塞 v2.0。
- **P3**：更远期的探索方向，允许被替换或取消；进入开发前必须先拆成 P1/P2 级别的可验收条目。

**状态约定**

- `⬜ 未开始` · `🚧 进行中` · `✅ 已完成` · `⏸ 暂停` · `❌ 取消`
- 子项用 `- [ ]` / `- [x]` 勾选；只有验收通过才允许勾选。

**进度维护**

1. 完成子项 → 勾选本文件对应条目，并更新 `ROADMAP.md` 的里程碑状态与百分比。
2. 新增需求 → 先归入某个阶段（P1/P2/P3），不允许存在“无阶段需求”。
3. 跨阶段移动或取消 → 在 §4 变更记录追加一行，并同步 `ROADMAP.md`。

## 1. P1（v2.0）

**目标**：把 image-view 从“能看图”升级为“日常主力看图 + 轻量管理”，覆盖格式、色彩、连续浏览、基础编辑与可分发安装。

**非目标**：RAW、AI、云同步、移动端（均属 P2/P3）。

**发布门槛**：P1-M1 ~ P1-M5 完成，且 P1-M7 的安装器与文件关联可用 → v2.0；P1-M6（图库/编辑）与 P1-M7 的自动更新/多语言可拆分为 v2.1 / v2.2。

### 1.1 P1-M1 桌面集成与持久化（0.5~1 d）

- [ ] 记住窗口大小、位置、最大化状态（`eframe` persistence 或 `%APPDATA%\image-view\settings.json`）。
- [ ] 记住上次目录：无命令行参数启动时恢复到上次浏览位置。
- [ ] 记住当前目录内的浏览位置与排序方式。
- [ ] 删除到回收站（`trash` crate；`Delete` 键 + 工具栏/右键菜单）。
- [ ] 复制文件路径（`Ctrl+Shift+C`）与“在资源管理器中显示”。
- [ ] 设置文件损坏、无权限或版本过旧时回退默认值，不阻塞启动。

**验收**

- 调整窗口 → 退出 → 重启，尺寸/位置/目录/图片序号全部恢复。
- 删除当前图片后自动前进到下一张；目录清空时回到空状态。
- 只读目录、ACL 拒绝场景不 panic、不产生错误横幅噪音。

**风险**：跨平台配置目录差异 → 统一走 `dirs` crate；未来设置项增多时再抽 `settings.rs`。

### 1.2 P1-M2 动画格式（1~1.5 d）

- [ ] GIF / WebP 动画逐帧播放，加载完成前先显示首帧。
- [ ] 播放 / 暂停控制；循环次数遵循文件元数据，异常值兜底。
- [ ] 帧间隔按 GIF delay / WebP duration 计时，异常 delay（0 或超大）钳制到 50~1000 ms。
- [ ] 逐帧上传纹理、及时释放旧帧，复用现有 `Caps` 限制总像素。
- [ ] 与幻灯片共存规则：`Space` 优先控制当前动画；无动画时才控制幻灯片，并在状态栏注明当前绑定。
- [ ] 切换图片、暂停后重置播放状态；动画不参与 LRU 主缓存。

**验收**

- 10 MB GIF 播放不卡顿、不持续增长内存；暂停后 CPU 接近 0%。
- 切换图片立即停止动画；再切回时从首帧重新播放。

**风险**：`image` crate 的动画 API 能力有限 → 先做 1 天 PoC；必要时引入 `gif` / `webp` 专用 crate。

### 1.3 P1-M3 色彩管理与高位深（1.5~2 d）

- [ ] 读取 JPEG/TIFF/PNG/WebP 内嵌 ICC profile。
- [ ] 用 `lcms2` 将源色彩空间转换到 sRGB 后再生成纹理。
- [ ] 16-bit PNG/TIFF 在转换阶段保留色深，最终输出 8-bit 纹理（显示端仍为 8-bit）。
- [ ] 无 ICC 时按 sRGB 处理；profile 解析/转换失败时回退原像素并写 debug 日志。
- [ ] 状态栏可显示“已色彩转换”标记（可选，默认关闭）。

**验收**

- 带 AdobeRGB / Display P3 profile 的图片与系统查看器、浏览器颜色接近（同屏对比）。
- 16-bit 渐变图不出现明显色带；转换失败的图片仍可正常显示。

**风险**：`lcms2` 原生依赖与体积 → 使用 feature gate，Windows 走预编译；作为可选组件评估。

### 1.4 P1-M4 HEIC / AVIF（1~1.5 d）

- [ ] AVIF 解码（`avif-native` 或 `image` 新增特性），扩展名与文件过滤器同步。
- [ ] HEIC 解码（`libheif-rs`，Windows 需随包分发 DLL）。
- [ ] 缺失解码器时给出明确错误文案，而不是“格式不受支持”泛化提示。
- [ ] 评估安装包体积与许可；默认构建可关闭，安装器提供可选组件。

**验收**

- iPhone 导出的 HEIC 与 AVIF 样例正常显示、可旋转、可翻页。
- 无解码器的构建打开对应文件时提示清晰、不崩溃。

**风险**：C 依赖、许可与体积 → 优先 AVIF；HEIC 若使安装包增加超过 15 MB，则推迟到 v2.1。

### 1.5 P1-M5 浏览体验（2~3 d）

- [ ] 缩略图条 / 胶片模式：当前目录、懒加载、虚拟滚动。
- [ ] 缩略图磁盘缓存（`%LOCALAPPDATA%\image-view\thumbs`，键 = 路径 + 修改时间 + 目标尺寸）。
- [ ] 缩略图内存 LRU（建议 512 张、单张 ≤ 160 px），与主纹理缓存预算分离。
- [ ] 缩略图预加载：预取当前项前后各 3 张，命中缓存时不重新解码。
- [ ] Mipmap / 过滤模式随缩放自适应：缩小用 mipmap + LINEAR，100% 附近保持清晰。
- [ ] 缩略图条内方向键/滚轮导航，与主画布同步。

**验收**

- 1000 张目录滚动缩略图流畅（60 fps）；冷启动首屏缩略图 1s 内出现。
- 点击相邻图片 < 100 ms 显示（命中纹理或缩略图占位）。
- 3000 张目录内存增长受控（缩略图缓存有明确上限）。

**风险**：显存/内存增长 → 缩略图独立预算 + 磁盘缓存；大目录扫描慢 → 后台增量索引（与 M6 共用）。

### 1.6 P1-M6 图库与编辑（4~6 d，可拆为 v2.1 / v2.2）

- [ ] 图库模式：后台目录索引、网格视图、按名称/日期/尺寸/格式筛选。
- [ ] 搜索：文件名子串、标签；标签写入 sidecar JSON，不污染原文件。
- [ ] 对比模式：2~4 张并排或叠加，同步缩放与平移。
- [ ] 基础编辑：旋转/翻转/裁剪、格式转换与另存（JPEG/PNG/WebP，质量选项）。
- [ ] 非破坏原则：编辑默认只写副本；覆盖原文件必须二次确认。
- [ ] 另存时应用 EXIF 方向、保留可保留的元数据。

**验收**

- 1 万张目录进入图库 < 2s（索引可后台继续），滚动不卡死。
- 另存结果与画布显示一致（含旋转方向）；原文件不被隐式修改。
- 对比模式下两张不同尺寸图片可同步缩放、平移。

**风险**：范围膨胀 → 先交付“图库浏览 + 旋转/另存”，裁剪与其他编辑放到 v2.2。

### 1.7 P1-M7 发布工程（2~3 d）

- [ ] 安装器（Inno Setup 或 WiX）：安装、卸载、开始菜单、可选“设为默认看图程序”。
- [ ] 文件关联：注册支持的扩展名，资源管理器“打开方式”可用。
- [ ] 自动更新：检查发布清单、下载、哈希/签名校验、失败回滚；默认手动确认。
- [ ] 多语言：中/英 UI 资源表（轻量方案优先，如自写 `fl!` 宏或 `rust-i18n`）。
- [ ] 崩溃日志落盘；匿名统计默认关闭且需明示。
- [ ] 版本号与 CHANGELOG 规范：`v2.0.0` 起语义化版本。

**验收**

- 干净 Win10/11 虚拟机：安装 → 双击图片 → 关联生效 → 升级 → 卸载无残留。
- 升级失败时保留旧版本可回退；无网络时手动检查更新有明确提示。

**风险**：代码签名证书成本 → 首版可无签名并说明；企业分发/策略管理放 P3。

## 2. P2（v2.x）

> P2 不阻塞 v2.0；每项开始前需要拆成带验收标准的任务清单。

### 2.1 P2-1 RAW 支持

- 目标：CR2/CR3/NEF/ARW/DNG 等常见 RAW 的首帧预览与基础解码。
- 要点：`rawloader` / `libraw` 绑定；先做内嵌 JPEG 预览，再做全尺寸解码；色彩矩阵与白平衡最小可用。
- 依赖：P1-M3 色彩管理。
- 风险：格式碎片化、解码慢、许可差异 → 按相机型号分批支持。

### 2.2 P2-2 HDR / 10-bit 完整链路

- 目标：HDR PNG/AVIF/HEIF 与 10-bit 显示器上的正确显示。
- 要点：wgpu 表面格式与色调映射；`egui` 纹理格式限制评估；SDR 回退策略。
- 依赖：P1-M3。
- 风险：egui/eframe 对浮点纹理与色彩空间的支持有限 → 可能需要绕过 `TextureHandle` 直接走 wgpu。

### 2.3 P2-3 分块流式加载与 GPU 解码

- 目标：超大图（>250 MP）与网络路径可渐进显示；解码不阻塞交互。
- 要点：tile 金字塔、按视口请求、后台多重解码、GPU 解码（D3D11VA/NVDEC）评估。
- 依赖：P1-M5 缩略图/索引架构。
- 风险：复杂度高，收益集中在极端尺寸 → 先做“低分辨率占位 + 全图替换”的渐进方案。

### 2.4 P2-4 插件与脚本扩展

- 目标：第三方格式解码、导出、批处理自动化。
- 要点：稳定插件 ABI 或 WASM 沙箱；能力授权（只读/写盘）；插件清单与签名。
- 风险：安全与兼容成本高 → 先内部脚本（Rhai/Lua）后开放生态。

### 2.5 P2-5 设置、主题与快捷键自定义

- 目标：可视化设置面板；浅色/跟随系统主题；快捷键重绑定。
- 要点：设置 schema 版本迁移；冲突检测与恢复默认。
- 依赖：P1-M1 的持久化基础。

### 2.6 P2-6 多窗口、多显示器与会话

- 目标：独立窗口打开多张图；跨显示器 DPI 变化正确处理；会话恢复。
- 要点：每窗口独立 `ViewState` / `folder`；共享缓存与解码线程；窗口级快捷键作用域。
- 风险：egui 多 viewport 支持与 DPI 切换的边界行为需专项测试。

### 2.7 P2-7 超大型目录与缓存架构

- 目标：10 万+ 文件目录可用；索引与缩略图缓存可持久化、可清理。
- 要点：SQLite 索引（路径、mtime、尺寸、标签）；缩略图磁盘 LRU；后台增量扫描。
- 依赖：P1-M5 / P1-M6。

## 3. P3（v3+，新增长期计划）

> 本节为**新增**的长期方向，均未排期。进入开发前必须先在 §4 记录变更并拆成可验收任务。

### 3.1 P3-1 云同步与分享

- 目标：从 WebDAV / S3 / 图床直接浏览与上传；生成分享链接。
- 要点：凭据安全存储（Windows Credential Manager）、断点续传、只读缓存。
- 风险：网络错误处理与隐私；默认关闭。

### 3.2 P3-2 AI 辅助

- 目标：本地或可选的模型能力，如超分、去噪、背景移除、自然语言搜索。
- 要点：优先本地推理（ONNX Runtime / DirectML），模型按需下载；明确标注“AI 处理结果”。
- 风险：模型体积、硬件差异、隐私与许可证。

### 3.3 P3-3 移动端 / Web

- 目标：复用解码、缓存、视图数学等核心 crate，提供平板/浏览器版本。
- 要点：先把平台无关逻辑抽成 `image-view-core`；Web 端用 WASM + Canvas/WebGPU。
- 风险：`egui` 在移动端/触控交互的成熟度；文件系统访问差异。

### 3.4 P3-4 插件市场与主题生态

- 目标：插件/主题的浏览、安装、更新与评分。
- 要点：清单签名、版本约束、崩溃隔离；服务端成本评估。
- 依赖：P2-4、P2-5。

### 3.5 P3-5 协作标注与审阅

- 目标：图片上标注、评论、版本对比，适合设计/摄影审阅流程。
- 要点：标注以 sidecar 保存；可选共享链接；权限模型。
- 风险：从单机工具转向协作产品的范围跳跃 → 仅在明确需求后启动。

### 3.6 P3-6 企业部署与可管理性

- 目标：MSI/企业分发、组策略模板（ADMX）、代理与离线更新、审计日志。
- 要点：静默安装、配置锁定、可选遥测。
- 依赖：P1-M7 发布工程。

## 5. 发布与质量门禁

每个里程碑合并前必须通过：

```text
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test
cargo build --release
```

发布前额外要求：

- 更新 `ROADMAP.md` 阶段状态与“最近完成”记录。
- 在 `PLAN.md` 或本文件补充对应验收记录（环境、方法、实测数据、未覆盖项）。
- 手工回归 `PLAN.md` §9.2 矩阵中受影响的类别；新增格式/解码器需补夹具。
- 记录 release 体积、启动时间、目标场景内存占用；超出 `PLAN.md` §10 预算需说明原因。
